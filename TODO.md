# StarJar delivery outcomes

- [x] **Repair high-impact reliability and safety issues in the existing StarJar app.** Preserve the existing application and routes; fix concrete server/client defects rather than rewriting the product. The documented `npm start` flow must serve pages and assets alongside API routes. Production must not silently use a known development JWT secret. Pomodoro completion requests must accept only supported, valid focus/break lengths so XP cannot be minted by arbitrary durations. Clearly identify that the current JSON-file database cannot provide durable shared storage on Vercel/serverless without an owner-provided database.
- [x] **Make study progress and timer behavior accurate and resilient.** “Tasks completed today” must count completions for the current day, not all historical completed tasks. An in-progress focus timer should survive an accidental page refresh and a completed session must not award the same reward twice. Correct the landing-page claim that mood logging grants XP if mood check-ins do not grant XP.
- [x] **Make the existing experience extremely whimsical, welcoming, and game-like for a broad range of learners.** Keep the existing Storybook Journal visual system and five additional themes; refine hierarchy, feedback, and microcopy across landing/dashboard while retaining the task, focus, recharge, progress, account, and theme flows. Rewards must celebrate effort without shaming missed days, requiring every optional wellness action, or relying on gendered assumptions. Preserve keyboard visibility, mobile usability, and reduced-motion support.
- [x] **Deliver the changes safely to the user's repository.** Keep secrets and personal data out of commits; run available application/API checks; report any production database prerequisite that cannot be completed without the owner's credentials or hosting setup.
- [x] **Polish the StarJar identity and account entry screens.** Change the visible product name from “StudySync” to “StarJar”; remove the visible logo from the landing, login/signup, and dashboard screens; use a more aesthetic, consistent Fraunces/DM Sans/DM Mono type system; and make the login/signup “back home” link easy to see and reliably navigate to the landing page.
- [ ] **Persist every user's StarJar account and study progress in hosted Postgres while keeping Vercel as the API host.** Select Postgres when `DATABASE_URL` is configured; preserve a JSON-file adapter only for local development; in Vercel/production, never use a local file or `/tmp` as account storage and return a clear setup error if the database is not configured. Preserve the current API paths and responses for signup/login, per-user tasks, XP/levels/streaks, moods, Pomodoro sessions, water logs, and achievements. Enforce user ownership, unique email, one mood and water record per user/day, and idempotent focus-session rewards with parameterized SQL and transactions. Document the required Vercel `DATABASE_URL` and `JWT_SECRET` setup and redeploy step; leave this outcome open until the owner connects the database and live signup/login are verified.
